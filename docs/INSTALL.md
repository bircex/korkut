# Installation

Korkut runs locally with Docker Compose: one office, on its own machine.

## Prerequisites

- Docker with Compose v2.

## Install

From the repository root:

```bash
./install.sh
```

On Windows, in PowerShell: `.\install.ps1`.

The installer writes the model gateway's two secrets and the admin's first password to `.env`
(once; running it again never changes them) and starts everything with `docker compose up -d --build`.
Then open <http://localhost:8090>. Every other setting has a local default, and the app's signing and
2FA keys are generated on first start.

**Keep a copy of `.env`.** `LLMR_MASTER_KEY` in it seals the AI provider keys you enter; without
it they cannot be read back.

## Signing in

Every installation has one admin account, created on first start:

- user name: `korkut-admin`
- password: generated by the installer, printed at the end of the install and kept in `.env` as
  `KORKUT_ADMIN_PASSWORD`

Sign in with it, change the password (Ayarlar → Hesap), then invite the other members from
Ayarlar → Üyeler; they join with their e-mail and a password of their own. The office is named
"Hukuk Bürosu" unless `KORKUT_OFFICE_NAME` is set in `.env` before the first start.

The password in `.env` is only the first one. If the admin's password is lost, run:

```bash
./install.sh --reset-admin-password
```

(`.\install.ps1 -ResetAdminPassword` on Windows). It writes a new password to `.env`, prints it, and
the admin's other sessions end.

To change a setting (the port, SMTP), add it to `.env` (see
`.env.example`) and run `./install.sh` again. Updating Korkut is the same: pull the new version
and run the installer.

## Where your data lives

| Volume | What |
|---|---|
| `pgdata` | The database |
| `objects` | Uploaded documents |
| `secrets` | The generated `KORKUT_SECRET` and `KORKUT_TOTP_KEY` |
| `llmr-data` | The model gateway: providers, models, routes and usage, keys sealed with `LLMR_MASTER_KEY` |

All of them survive rebuilds and upgrades. Back them up together with `.env`. `docker compose down` stops
Korkut; `docker compose down -v` also deletes all data.

Korkut listens on `127.0.0.1` only. Set `KORKUT_BIND_ADDRESS=0.0.0.0` to reach it from other
machines on your network.

## Choosing the AI models

Every model call goes through the model gateway (llmr) that the installer starts. After the first
sign-in, the office owner opens **Ayarlar → Yapay zeka**, adds a provider (a cloud API key, or a
local server such as Ollama or LM Studio at `http://host.docker.internal:<port>/v1`), tests it, and
picks the chat model and, for searching uploaded documents, an embedding model. Provider keys are
kept sealed in the gateway, never in `.env`, and the same screen shows the last 30 days' usage and
cost.

Documents uploaded before an embedding model was chosen are not searchable until they are indexed
again.
